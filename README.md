# Практическая работа №2. Граф зависимостей NuGet

**Дисциплина:** Конфигурационное управление  
**Группа:** ИКБО-22-25  
**Вариант:** 20  
**Язык:** Python 3.9+

## Описание

Консольный инструмент для анализа зависимостей пакетов NuGet.

- **Этап 1:** чтение CSV, проверка и вывод пяти параметров.
- **Этап 2:** загрузка прямых зависимостей конкретной версии через NuGet V3.
- **Этап 3:** рекурсивное построение транзитивного графа алгоритмом DFS,
  обнаружение циклов и поддержка локального тестового репозитория.

Для получения зависимостей используются только стандартные библиотеки
Python; готовые менеджеры пакетов и сторонние библиотеки не применяются.
Граф пока выводится текстом: создание PNG относится к пятому этапу.

## Структура проекта

- `src/config.py` — загрузка и проверка CSV.
- `src/nuget.py` — получение прямых зависимостей из NuGet V3.
- `src/graph.py` — чтение тестового графа и рекурсивный DFS.
- `src/frameworks.py` — выбор группы зависимостей для платформы .NET.
- `src/versions.py` — выбор подходящей версии в диапазоне NuGet.
- `src/nuget_graph.py` — загрузка транзитивных зависимостей.
- `src/main.py` — интерфейс командной строки.
- `examples/` — тестовые репозитории и конфигурации.
- `tests/` — тесты и демонстрации всех трёх этапов.
- `config.csv`, `run.sh`, `.gitignore` — настройки и запуск.

## Конфигурация

Конфигурационный файл содержит два столбца: `key,value`.

| Параметр | Назначение |
| --- | --- |
| `package_name` | Имя исследуемого пакета |
| `repository` | Индекс NuGet V3 или файл тестового графа |
| `test_mode` | `true` — локальный файл, `false` — NuGet |
| `package_version` | Версия пакета |
| `output_file` | Имя будущего изображения PNG |

Пример стандартного `config.csv`:

```csv
key,value
package_name,Newtonsoft.Json
repository,https://api.nuget.org/v3/index.json
test_mode,false
package_version,13.0.3
output_file,dependencies.png
```

В тестовом режиме путь `repository` отсчитывается от CSV-файла.
Названия тестовых пакетов состоят только из заглавных букв `A-Z`.

## Запуск

Сборка и сторонние зависимости не требуются. На macOS/Linux:

```bash
./run.sh
./run.sh --config-only
./run.sh --framework netstandard1.0 --max-seconds 60
python3 -m tests.demo_errors
python3 -m tests.demo_stage2
python3 -m tests.demo_stage3
python3 -m unittest discover -s tests -v
```

По умолчанию для транзитивного графа выбрана платформа `net6.0`.
Флаг `--framework` позволяет выбрать другую целевую платформу.
Ограничения `--max-nodes 80` и `--max-seconds 30` предотвращают
неконтролируемый обход: при превышении выводится ошибка вместо
неполного графа. Значения можно изменить через флаги.

Получение прямых зависимостей по-прежнему показывает все группы из
манифеста. В рекурсивном обходе используется одна совместимая группа.
Версия каждой зависимости выбирается как минимальная доступная,
удовлетворяющая указанному диапазону NuGet. Глобальное разрешение
конфликтов версий между разными ветвями здесь не выполняется.

## Тестовый режим

Формат графа: одна строка на пакет, например:

```text
A -> B, C
B -> D
C -> D
D -> A
```

Для узла без зависимостей используется `D ->`.
Упоминание пакета справа от стрелки без собственной строки допустимо:
он считается вершиной без зависимостей.

Три готовых сценария запускаются одной командой:

```bash
python3 -m tests.demo_stage3
```

Либо по отдельности:

```bash
./run.sh --config examples/config_cycle.csv
./run.sh --config examples/config_diamond.csv
./run.sh --config examples/config_no_deps.csv
```

Первый пример содержит цикл `A -> B -> D -> A`, второй — общий узел
`D` без цикла, третий — пакет `A` без зависимостей. Тестовый режим
не требует интернета.

## Как работает третий этап

1. Для пакета из CSV получаются прямые зависимости через NuGet V3.
2. Для каждой зависимости выбирается подходящая версия, затем её
   зависимости обрабатываются рекурсивным DFS.
3. Посещённые вершины сохраняются. Обратное ребро к активной вершине
   указывает на цикл; повторно обходить её не требуется.
4. Результат выводится как набор связей с числом узлов, рёбер и циклов.

Для сетевых запросов нужны доступ к интернету и работающий NuGet API.
Ошибки CSV, отсутствующих пакетов, формата данных и лимитов обхода
завершают программу с ненулевым кодом возврата.

Документация формата: [NuGet Service Index](https://learn.microsoft.com/nuget/api/service-index),
[Flat Container](https://learn.microsoft.com/nuget/api/package-base-address-resource),
[NUSPEC](https://learn.microsoft.com/nuget/reference/nuspec).
